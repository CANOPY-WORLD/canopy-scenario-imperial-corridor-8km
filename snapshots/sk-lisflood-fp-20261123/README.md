# SK LISFLOOD-FP recorded rain experiment

A 1 m, 3.2 km square South Kensington/Hyde Park experiment within the London Scenario. [Open the report](index.html), [watch the MP4](media/sk-rain-overview.mp4), or [use the GIF](media/sk-rain-overview.gif). This snapshot is a separate research report; it is not the shared Viewer's selected flood layer or a V2 scientific Asset.

The input ZIP starts from the accepted corrected terrain and six-hour warmed lake state. It includes native rainfall/run inputs, masks, portable verification/build/run/audit code, the exact local GPU ACC FP64 correction, source hashes, dependency locks and source notices. See [reproduction instructions](REPRODUCE.md). The main repository also supplies this helper as `urban_flow.lisflood_case`; no new registered Method is claimed.

## Scientific scope

Uniform synthetic 49.95 mm rain over 90 minutes; native run continues to 180 minutes. The 7-second, 70-frame animation covers only 0–105 minutes, with linear interpolation between approximately 15-minute solver snapshots. Teal indicates existing water, grey buildings; the flood depth scale applies to land. No infiltration, sewer drainage, roof runoff redistribution or fixed lake-stage maintenance is enabled. Surface redistribution and boundary outflow remain possible.

The coordinate system is EPSG:27700, bounds [525000, 177800, 528200, 181000], with ODN terrain/water elevations. Depth is metres above the modified bed. No automatic conversion to Canopy's local/terrain-normalized 3D coordinates is included. The SK focus rectangle is not an official campus boundary.

The terrain includes full nonwater depression filling, buildings extracted using DSM within OSM footprints, and trial flat lake beds. Some large terrain edits remain review flags. DSM-based normal levels are trial values, not observations; Round Pond's depth is assumed. The static lake check preserves the initial wet footprint for six hours without point sources.

The original 3-hour corrected run conserves volume to a maximum sampled residual of 4.7630130097786605e-6 m³. That is numerical evidence, not validation against a measured storm. The 5.277 m maximum land depth occurs in an isolated cell beside buildings and remains a terrain-review flag. The included review map and locations make that limitation visible.

A [packaging reproduction check](metadata/reproduction_check.json) rebuilt the pinned solver and reran 30 simulated minutes from the distributed ZIP. All three native depth snapshots match the original recording byte for byte, and the independent volume audit passes. This is a bounded check, not a new full 180-minute run.

## Files and precision

- `downloads/`: immutable rerun package, with the byte-exact native inputs. Raw native time series are regenerated by running it; no precompiled solver binary is shipped.
- `gis/depth_090min_1m.tif`: float32 total water depth at the actual saved time 5400.047043786597 s, including roof and lake cells.
- `gis/max_depth_land_only_1m.tif`: float32 per-cell maximum over the full 180-minute run, excluding roofs/existing water. It is not a simultaneous inundation map or just the animation window.
- `gis/cell_type_1m.tif`: 1=land, 2=roof excluding water, 3=protected/initial water. Preserve masks; nodata is not dry land.
- `figures/`: original English workflow, terrain, initialization, rainfall and deep-cell diagnostics.
- `diagnostics/` and `metadata/`: sampled volumes, actual times, assumptions, source and solver hashes. Local machine paths were replaced by source labels; scientific values and original hashes were retained.

Native float64 ASCII depths were used for volume checks. Float32 GeoTIFFs and interpolated video frames are presentation products. Native velocity outputs use staggered faces and must not be reinterpreted as cell-centred vectors.
